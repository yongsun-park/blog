PCB 설계 데이터를 조회하는 `coco CLI` 호출 프롬프트를 최근 조금 수정했습니다.

큰 변경은 아니어서 기존 기능에는 별 영향이 없을 것으로 생각했어요. 그런데 내부 PCB 벤치를 다시 돌리니, 이전에 통과하던 테스트가 실패했습니다.

AI 솔루션의 품질은 모델 하나로 결정되지 않는 것 같습니다. 프롬프트, Tool 설명, 실행 환경과 CLI 버전이 함께 움직이고, 그중 하나만 바뀌어도 Agent가 도구를 선택하고 실행하는 흐름이 달라질 수 있어요.

모델 성능이 좋아졌다고 특정 업무까지 항상 좋아진다는 보장도 없습니다. 새 모델이나 프롬프트를 적용할 때마다 기존 기능을 다시 확인해야 하는 이유입니다.

PCB 설계 조회라면 최종 답변만 볼 수도 없습니다. 올바른 명령과 도면을 사용했는지, 조회한 Net·Component·Layer와 수치가 맞는지, 도구가 실패했는데도 답을 만들어 내지는 않았는지 함께 확인해야 합니다.

벤치마크는 모델 순위를 정하는 시험이기도 하지만, 제품을 만드는 입장에서는 어제 되던 기능이 오늘도 되는지 확인하는 장치에 더 가까운 것 같아요.

기술 변화가 빠를수록 실제 업무를 담은 내부 테스트 케이스가 더 중요한 제품 자산이 되지 않을까 싶습니다.
