Agent용 PCB 조회 도구는 기능 구현만으로 완성되지 않았습니다.

PCB 데이터를 정확하고 빠르게 조회하는 프로그램을 만들면 기본 기능은 갖춰집니다. 하지만 실제 Agent에 연결해 보니 확인할 일이 더 많았어요.

조회 함수가 정확해도 Agent가 질문에 맞는 도구를 고르지 못할 수 있습니다. 파라미터를 잘못 구성하거나, 정상적인 결과를 받아 놓고 다른 의미로 해석할 수도 있고요.

기능이 늘어나면 도구의 이름과 설명, 기능을 나누는 기준도 중요해집니다. 반환하는 정보가 너무 많으면 오히려 Agent가 핵심을 놓칠 수도 있습니다.

그래서 PCB 조회 도구에는 여러 층의 테스트가 필요했습니다.

- PCB 데이터를 정확하고 빠르게 찾는 기능·성능 테스트
- 질문에 맞는 도구와 파라미터를 고르는 Agent 테스트
- 사용자 질문부터 최종 답변까지 확인하는 End-to-End 테스트
- 모델·프롬프트·도구 변경 뒤 다시 확인하는 회귀 테스트

테스트 결과를 보며 도구의 범위와 설명, 반환 형식을 다시 바꾸게 됩니다. 벤치가 개발 마지막의 검사가 아니라 도구를 설계하는 과정에 들어오는 셈이에요.

이제는 도구의 기능과 Agent의 활용 성능을 함께 개발해야 하는 것 같습니다.
